# Cross-Carrier Assertion Consistency

> Load-chain：本檔由 `code-review-checklist.md` 軸 1 按需載入；entry 只留 pointer。非跨 carrier 變更時可不讀。**修復時同樣觸發**：TL 收到任何 review／cross-model 標記的 cross-carrier assertion finding（Important/WARN），在動手修正前 MUST 先載入本檔並套用下方窮盡律，不得只憑 AGENTS.md §0 第10條摘要即動手——逐輪只改被點名那一處是本檔窮盡律明文禁止的失敗模式（見本檔下方 PR #1462 前例；PR #2361 為同一失敗模式在 remediation 端的複現，兩輪 cross-model review 才逐一挑出同一斷言的四個副本——round-1 六軸 review 未抓到任何一處）。

- **Cross-Carrier Assertion Consistency sub-check（semantic discovery cooperative-only）**：PR 改動一個**跨 carrier 語意斷言**（fail-open／fail-closed 方向、契約、常數值、polarity——意義散落在 code + spec delta + canonical + narrative（brd/proposal/meeting-notes/tasks）多處）時，reviewer **必須**確認全副本已**一次對齊**：對該斷言 grep 全部中英正反向變體，逐一核對是否同步。Reviewer 同時必須抽查 proposal/proposal-mini `## Requirement Ledger` 的 `Current Requirement` 欄、由 requirement 派生的 tables/threshold/counts、QA/test-scope/PR/comment closeout prose；宣稱「已記錄/already recorded」須有目標 carrier grep evidence；PR body / sticky / issue comment / Recap 等重寫留言須對 final commit state 重讀；派生數字須從 final merge-base→HEAD script/command 重算；同一 canonical spec 內同機制 requirement 的 precision level（例如 lexical + realpath + bidirectional path containment）不得一處精確、一處 vague。發現**殘留未同步的副本**、或同一機制的 code↔narrative 兩處**自相矛盾**（如一處寫 over-remind、另一處寫 under-remind）→ 標 **Important**（附各副本 `file:line`）。**窮盡律**：cross-review（含本軸）指出某斷言 polarity/契約錯時，**第一次修正就 MUST grep 全副本一次改完**，禁止逐輪只改被點名那一處——逐輪單副本修正會讓同一斷言在不同 carrier 每輪被重抓（本 session PR #1462 前三輪即反例，被抓四輪）。**窮盡掃描的 key 選錯，窮盡本身就是假的**：以**舊字面**為 key 只能證明**該字面消失**，證明不了**該語義消失**——同義改寫、中英互譯、換 symbol 名、換載體都讓舊字面歸零而語義仍在。「grep 舊字面回 0 命中」**MUST NOT** 單獨作為窮盡的驗收條件；驗收條件 MUST key 在**語義不變量**，字面 grep 只是逼近手段：先寫出判準句，據判準列出承載它的字面集合（含對向極性、改寫後長相）掃，掃完 MUST 反向抽查命中與未命中處，確認沒有「字面沒中但語義還在」。 **截斷掃描 ≠ 窮盡**：帶 pagination／`head_limit`／`max_results`／`[truncated]` 標記的搜尋輸出 MUST NOT 作為跨 carrier 窮盡證據（對齊類 self-alignment 同規；見 `chore-classification.md` §對齊類 chore A 必驗；`token-frugal-io.md` 限縮輸出不得被誤讀成可拿殘段當全量結論）。收到 sealed cross-carrier finding 後，remediation closure MUST 把該判準句、literal variants 與 current-HEAD 全命中 ledger 交給 `review-remediation-evidence` family；`--pre-review` 在下一輪 dispatch 前要求 current-HEAD declared-literal replay closure，重播固定字串，未申報／不存在命中或非封閉 disposition 一律 fail closed。此 mechanical gate **只證明作者已宣告搜尋集合的 coverage**、沒有 generic semantic oracle：同一斷言多種合法字面、跨檔語意判斷仍無零誤判的通用 semantic gate，invariant 正確性與未宣告同義句仍由本 leaf／reviewer 判斷。與上方 §Spec↔Code sub-check 的差別：那條驗「單一 spec scenario ↔ code 行為」；本軸驗「**同一語意斷言的所有副本彼此一致**」跨 code+spec+narrative。**分級預設 Important**（Critical 仍留給 correctness/security 缺陷）。適用 `dp-reviewer` 與 `devpro:second-review`（後者由 renderer 動態讀同一 checklist 進 packet，無需改 agent 檔）。前饋（寫入當下 grep 全副本）見 `openspec-quality-and-formats.md` §Writing Spec Deltas「跨 carrier 語意斷言同步」。SSOT：`openspec/specs/openspec-flow/spec.md` §Cross-Carrier Assertion Synchronization。

- **排除清單窮盡性（cooperative-only）**：宣稱 SHA／evidence carrier 排除清單完整時，MUST 先寫語義判準（哪些載體會保存或引用該 SHA／evidence）與搜尋範圍，掃中英／symbol 變體並保存未截斷全量命中；每個命中 MUST 列 disposition，排除者逐項附理由，並反向抽查未命中處。只列已知例子、舊字面零命中或截斷輸出 MUST NOT 充當完整性證據。此為本檔既有窮盡律在排除清單的用法，不增加 generic semantic oracle；`pre-pr/references/full-review-and-archive.md` pre-review 第 6 項是 action point。
