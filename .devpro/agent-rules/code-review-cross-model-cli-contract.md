# Cross-Model External Reviewer CLI Skill Contract

> Load-chain：本檔由 `code-review-cross-model.md` on-demand 指到；一般 session 不 eager-load，只有 dispatch 外部 reviewer CLI 時讀。

### External Reviewer CLI Skill Contract

本段是所有 host 共用的 cross-review skill 入口；具體 CLI 名稱 / auth probe / flag / allowlist 只寫在 `platform-adapters/<runtime>.md`。

Loading contract：`.devpro/agent-skills-refs/autonomous-ai-agents/<runtime>/SKILL.md` 是 on-demand CLI 操作手冊，不是 always-loaded root instruction；一般 session 不自動載入，只有 `devpro:cross-review`、`devpro:pre-pr` cross-review step、reviewer agent、或 adapter 路由到外部 reviewer CLI 時才讀。adapter 是本 repo cross-review wrapper 的 SSOT；skill 補 runtime CLI 細節，並繼承 Hermes 已驗證的 CLI anti-hang rules：auth probe、bounded timeout、one-shot、PTY/tmux、activity heartbeat / progress events、stdout/stderr evidence。

呼叫外部 reviewer CLI 前 MUST：

1. 讀本節、對應 adapter、以及 sticky comment contract。
2. 先 probe CLI 可用性與 auth；sandbox 內 auth/network failure不可直接判 reviewer unavailable。Renderer-owned canonical `reviewer_cli_recipe.auth_preflight` 是 dispatch 前的機械防呆：help flags通過後、neutral cwd／invocation claim／reviewer spawn前，runner MUST以reviewer將繼承的相同`HOME`、`PATH`與session env直接執行recipe contract定義的family-exact command與success predicate；具體vendor命令只寫在對應adapter與mechanical recipe SSOT。只有exact success可保留`flags_supported`；nonzero／timeout／overflow／malformed／logged-out／restricted-HOME／ambiguous一律pre-spawn closed-terminal `reviewer_host_surface_unverified`，不得宣稱真正帳號未登入。Raw auth stdout/stderr須bounded memory-only，既有probe artifact只存allowlisted operational metadata；禁止raw、excerpt、hash、identity、token、path。fallback / `UNAVAILABLE` 前 MUST have host-surface evidence；sandbox/shim `Not logged in` 或 auth/network denied 只能標 `sandbox-surface-fault`，成功 init 的 `apiKeySource:none` 是中性 metadata。**Mechanical SSOT**：此分類 MUST 透過 `.devpro/scripts/hooks/lib/host-auth-surface.mjs` `classifyAuthSurfaceFault(exitCode, output)` / `isFallbackAllowed(...)` 判定，不得各自重推 pattern；`isFallbackAllowed` 為 false（含 unknown-surface 的 auth/network failure，fail-closed）時禁 fallback / `UNAVAILABLE`，必須先 host-rerun 或取得使用者明示拒絕。**`surface` 參數語意**：caller 在「於真正 host runner（非 sandbox）重跑」時 MUST 傳 `{ surface: "host" }`，此時即使 output 含 sandbox-limit 字樣也判 `host-fault`（合法 host-rerun 不被困為 sandbox-fault）；sandbox 內呼叫傳 `{ surface: "sandbox" }`；未知則省略（預設 fail-closed 視為 sandbox-surface-fault）。`surface` 由 caller 斷言、非從 output 推斷，故 noisy echo 不能偽造 host。
3. 優先使用 bounded non-interactive one-shot mode 與 structured output；若 adapter 證明必須 PTY，需明示原因。
4. Prompt 使用 tier / role 語言，不寫死具體 model 名；具體 model selector 由 adapter 決定。 未設定具名模型覆寫時，renderer MUST 先探測帳號／provider 可用的最高 capability tier 並釘選 exact model；以完整模型探測證據連同 selection 交給 recipe、effort probe 與 runner。最高模型與 effort／service tier 分開判定；禁止以 picker 預設、列表順序或僅版本較新取代能力排名。排名或相容性無法證明即停止，禁退回固定模型或較低 tier。具名覆寫仍優先；external-evaluator 不跑 CLI 模型探測。政策與證據 schema 的執行 SSOT 是 `highest-tier-reviewer-model.mjs` + `second-reviewer-cli-recipe-contract.mjs`。
5. Adapter MUST 指定sticky writer。Safe-mode gated-CLI family由wrapper先完整列舉canonical marker candidates（enumerate the complete canonical marker candidate set）形成 wrapper-owned `sticky_authority_snapshot`（complete及於元素層：每個comment MUST是帶逐字string `body`＋identity fields；缺欄→disposition blocked；細節見 `code-review-cross-model-dispatch-mechanics.md`／sticky-authority SSOT），再由renderer產生trusted `sticky_write_disposition`；authority mapping是`zero=create, one=update via sticky_write_exact_recipe`，`more-than-one or unresolved count/id=blocked with no write`且不得spawn。`pr-sticky` static duties只呈現該disposition的單一路徑；reviewer不得自行query/search target、重算authority、fallback或把`previous_sticky`當authority。Safe-mode packet MUST render one disposition-bound `sticky_write_exact_recipe`（`write-second-review-sticky-gated.mjs` + credential-gate sidecar）與 `sticky_write_readback_recipe`（`read-second-review-sticky-comment.mjs`）；MUST NOT expose raw `Bash(gh api:*)`、`{owner}/{repo}` or another executable placeholder。全 family sticky body 一律落reviewer自己的current neutral cwd body file（per-dispatch、repo外、spawn當下為空）；Codex exact recipe不再持有main-checkout `notes/tmp`的`--add-dir`授權，body file仍為自由檔名；safe-mode仍固定`cross-model-second-opinion.md`；forbid inline `--body`、worktree-internal sticky body staging、Task/subagent、repo/git write/merge。Renderer/validator固定static `write_path`；safe-mode若無`Write`必須pre-spawn fail closed，不得改用stdin/direct gh body carrier、另一action或alternate path；TL不代貼；footer=writer provenance。Permission denial只由`second-review-control-evidence.md` structured result承載。`retry_context`＝`{classification,sticky_verification}`（禁 CRITICAL 清單／null-as-string；由 `build-pr-sticky-handoff.mjs --attempt`＋`--retry-classification`／`--retry-sticky-verification` 產生，TL 不手改 handoff）；same-head retry 鏈 `previous_dispatch_id`。
   Writer完成exact gated write後MUST self-read-back HTTP 200 via `read-second-review-sticky-comment.mjs`（external-evaluator MAY use disposition-bound `gh api` read-back）。Update的comment ID/URL必須與disposition完全相同；create須回讀新ID且為post-write唯一authority。Body須符合marker、verdict、SHA、dispatch、reason與provenance；denied/failed gated write、404/mismatch或concurrent drift回`status: blocked`及null ID/URL，MUST NOT try another create primitive、replacement/fallback或成功`PASS|WARN|CRITICAL`。
6. Linked-issue PR context MUST be present before verdict；`linked_issue_context` route SSOT 是 `openspec/specs/cross-runtime-parity/spec.md` → `Requirement: External Reviewer Linked Issue Route`，本 leaf MUST NOT 重述 route How。A cross-repo linked issue is only annotated, never read (`code-review-cross-model-dispatch-mechanics.md` §Initial handoff builder：邊界與封包欄位). Missing issue context is an invocation/orchestration fault；先 route to corrected invocation，不得判 reviewer CLI unavailable。
7. Reviewer path unavailable → adapter 改 same-family fallback（標 reason/provenance），或 strict/no fallback 時由 host/wrapper 寫 audit-only `UNAVAILABLE` + `reason:` + `last_reviewed_sha:`；額度用盡（`quota-unavailable`）的判定、必要 evidence 與完整階梯見 `code-review-cross-model.md` §失效 Fallback，且同家族 fallback 仍須經正常 dispatch 產出 sticky。PR 不得缺 audit trail，host 不得把 failed findings 改寫成 `PASS | WARN | CRITICAL`。若current allowlisted orchestration fault，runner先產生immutable capsule並保留診斷；不得偽造或覆寫reviewer sticky。Consumer authority另依 `post-pr-completion-gate.md`：exact current-head marker-matching `PASS`可先行，`WARN`仍須無current fault與完整receipt chain。

Packet `approval_context`／`approval_resolution` 是歷史欄位名：pr-sticky 固定 `none`／`{"status":"not-required"}`，不是核准（`code-review-cross-model-dispatch-mechanics.md` §Initial handoff builder：邊界與封包欄位）；只有 builder 寫入。

Review-material ownership：renderer/shared validator 負責 route 與 completeness；packet-bounded family 只按 packet 宣告順序讀 validated renderer-owned material。validation fault 在 spawn 前交回 orchestration owner；reviewer 不得 discover、reconstruct、repair、fetch、list、glob material，或 fallback 到 live `gh pr diff`。stream-json family 既有 validated live-read route 不變；normative behavior 見 `openspec/specs/code-review-checklist/spec.md` → `Requirement: External Reviewer Packet Mode`。

Handoff `done_when`：bounded handoff MAY include `done_when`（string or ordered acceptance list）。`render-second-review-packet.mjs` MUST project non-empty `done_when` into framed Review Data as the packet key `done_when`；empty/omitted remains valid and MUST NOT invent acceptance criteria。`validate-second-review-packet.mjs` accepts that optional key。

Handoff 欄位上限：bounded handoff 的 string 欄位帶 byte 與 single-line 上限，SSOT 是 `.devpro/scripts/validate-second-review-packet.mjs`，本 leaf 不複製數值以免漂移。組 handoff 時不要憑印象猜長度——render 前先跑 validator，其錯誤訊息會具名欄位與該欄位的實際上限。

Timeout policy：兩個 external reviewer family 共用下列 wrapper-owned contract；不得由個別 adapter 縮短或改成互動式授權停點。

- Wrapper MUST capture stdout、stderr、child-process lifecycle，並在 child open 時每 `60s` 寫一筆 liveness sample：cumulative/delta bytes、`last_output_at`、`idle_duration_ms`、idle reference、last structured output、child still open；每筆 sample 以 byte delta + idle evidence 確認目前 output-progress／idle-duration evidence。第一個 output byte 之前 `last_output_at` MUST 保持 `null`，`idle_duration_ms` 以 `process_started_at` 為基準；有 output 後才改以真實 `last_output_at` 為基準，MUST NOT 把 process start 偽裝成 output time。Activity heartbeat / structured progress event（stream-json event、stderr growth、child lifecycle transition、PTY/tmux status、child heartbeat）是主要存活證據；stdout/stderr growth 只作 fallback，health probe 必須同看 child process、final JSON readiness、permission-denial evidence 與 sticky freshness。Sticky poll 本身不得 reset activity state，除非它觀察到 sticky create/update。這是 reviewer stream liveness／idle 檢查，不是 TL 對 agent/projection lifecycle 的 polling，也不是完成訊號；單筆 no-output sample 不得直接判 hang，callback/process close 才是 terminal completion signal。Permission denial只看typed-first structured control evidence；exact `type:result`、bounded valid `uuid`／`session_id`與`permission_denials: []`是明確no-denial，不得生成fault；相同空陣列若缺少該exact envelope或identity仍按unknown fail closed。
- Runtime 有 completion callback/event 時，TL MUST 註冊後等待 callback，不得 periodic poll / list-agents busy wait。只有 runtime 明確沒有 callback/event 且需要 active monitoring 時，才可每 `60s` bounded poll lifecycle/artifact/sticky，最多 30 次／`30m`。
- Packet/streaming/single-result mode 在 `15m` 尚未 terminal 時，wrapper MUST persist status checkpoint 並自動續跑；不得 kill transport，也不得等待使用者授權。兩家一律使用 `30m` total hard cap；到 cap 時先做 final completion/current-head sticky verification、classify，再自動終止 transport。持續輸出只證明活著，不得超過 hard cap。Do not remove the `30m` total hard cap or switch to no-total-timeout。
- Spawn failure、early non-zero exit、stderr auth/permission/schema error、`requires approval`/`permission_denials` MUST fail fast or retry with adapter flags。No stdout / silence MUST NOT alone 判 hang；先看 child-process、stderr、final JSON、permission denial 與 sticky freshness；denial依structured result，不得掃reviewer prose。
- 宣告 timeout、fallback、`UNAVAILABLE` 或 kill 前，host MUST先驗 structured result，再 final-verify PR sticky。Post-PR exactly-one canonical `PASS` + current head + matching marker dispatch先形成consumer authority，later fault仍記transport/finalization診斷且不要求receipt chain；`WARN`只有無current fault且complete correctly-bound completion/lineage chain才可完成post-PR gate。Actual merge hook Path F仍只依exactly-one canonical current-head `PASS|WARN`，不消費marker/fault/receipt。其餘仍 route to corrected invocation / narrower packet / focused sticky-refresh / Deep Review / `UNAVAILABLE`。

Max-turn fault、provider probe history、與 stale-sticky same-shape broad rerun timeout/error orchestration friction troubleshooting 見 `code-review-cross-model-rationale.md` 與 host adapter cold troubleshooting；該形狀不是 reviewer unavailable，且不得同形狀重跑。

Packet-mode tool clamp：when an adapter uses a CLI-specific built-in tool selector flag, that flag is for built-in tool names only (`Write,Bash` or `Read,Write,Bash`); scoped shell permission patterns (`Bash(gh api:*)`, `Bash(gh pr view:*)`, `Bash(node <absolute-linked-issue-reader> <validated-repository-slug>:*)`) belong in the adapter's scoped allowlist flag。A scoped allowlist alone is not a hard built-in tool clamp for agent/subagent surfaces, so adapter packet mode MUST use both controls when supported and still forbid `Task/subagent delegation` in the packet prompt. Unknown deny-list tool names remain ineffective warnings and MUST NOT be used as the primary guard. The default tool allowlist MUST NOT include Node/npm/full-suite/budget commands; if `permission_denials` block optional verification, sticky wording MUST NOT claim that denied check ran.
