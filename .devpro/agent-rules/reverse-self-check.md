# 反向自檢

## Overview

在三個時刻各問一次「反過來看會怎樣」，避免把宣稱當成證據。本 leaf 只提供指引與 Recap 落點，不是機械閘：不擋任何操作，但每次收尾要留三行紀錄，讓「有沒有問」變成可數的事實。

## When to Use

- 準備開始改東西（動手前）
- 正與使用者確認需求（談需求時）
- 準備說「做完了」或開 PR（交付前）
- 撰寫 Session Recap

## Rules

| 時刻 | 要問的 | 好的答案長什麼樣 |
|---|---|---|
| **動手前** | 這件事怎樣算失敗？哪一步若被跳過，會沒人發現？ | 具體失敗情境（哪個值、哪個狀態）＋具名承擔者；答「沒人」最有價值 |
| **談需求時** | 什麼情況算沒做完？誰會說「這不是我要的」？ | 至少一條可驗收條件（可測、可指名的輸出） |
| **交付前** | 我拿什麼當完成證據？這證據被反例打過一次嗎？ | 可指名的測試／指令輸出／review verdict，加一個「試過會失敗」的反例 |

**寫不出可驗的東西，就等於沒問。** 每格都要能被別人拿去核對；「風險可控」「團隊會看」「有考慮」屬未填。

**沒有反例的宣告，就是沒驗過的宣告。** 反例可以很便宜：塞一個明顯錯誤的輸入，確認檢查會紅。

Recap 落點固定三行：

```
## 反向自檢
- 動手前：問了 / 沒問 ｜ 失敗情境：<一句> ｜ 跳過誰會發現：<具名，或「沒人」>
- 需求：問了 / 沒問 / N/A（純技術任務）｜ 可驗收條件：<幾條>
- 交付前：證據：<一行> ｜ 反例：<我用什麼去試它會失敗>
```

## Exit Criteria

- 三行都寫了，且每格內容可被外人核對。
- 「沒問」照實寫，不為了好看補成「問了」。
- 反例寫不出來時寫「沒有反例」，不寫「已評估」。

## Common Rationalizations

| 藉口 | 反駁 |
|---|---|
| 「風險可控」 | 那不是答案，是形容詞；要寫出哪個值／哪個狀態會壞。 |
| 「團隊會看」 | 沒有名字就等於沒人；寫不出人就寫「沒人」。 |
| 「有考慮過了」 | 考慮不可核對；要留下可指名的輸出或反例。 |
| 「指引而已，不必認真填」 | 連續多個 session 都填空話，就是本指引無效的證據，該改設計而不是繼續填。 |

## Verification

- `node --test .devpro/scripts/tests/reverse-self-check-grep.test.mjs`（三時刻、三行、標準句、反例規則與 carrier 指向）。
- 抽查最近一份 Recap 是否含 `## 反向自檢` 三行，且每格可核對。

## 這個紀錄證明什麼、不證明什麼

證明：當時有沒有問、問出的東西是否可被檢驗。
不證明：答案誠實、或工作真的因此變好。若連續多個 session 都是「沒問」或全部空話，那就是指引無效的證據，應回頭改設計而不是加更多指示。
