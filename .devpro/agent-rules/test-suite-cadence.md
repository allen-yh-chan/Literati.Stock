# Test Suite Cadence

> Load-chain（entry）：本檔是 `testing-and-qa.md` § Source Repo Test Runtime Budget 的條件 leaf；TDD、RED 證據與 QA 報告留在 entry。本檔「依下方 Exit Criteria 的 suite×HEAD／digest 綁定段」所指段落未隨本檔搬移：指 entry `testing-and-qa.md` `## Exit Criteria` 的「測試證據為 suite×HEAD／digest 綁定」條。

### Source Repo Test Runtime Budget

Source repo (`devpro-agent-rules`) 測試執行採 **tier-aware、file-level 選擇性執行**——不是每次都跑 full suite。full suite 已 git-integration-heavy 且 CPU-bound，wall-clock 隨機器負載波動；固定 wall-clock 硬預算只逼出每 PR bypass、保護不了任何東西。取而代之：**日常/pre-PR 永遠跑完整 unit tier，integration 只選本 PR 新增或修改的 integration tests，加上以完整路徑引用被改腳本的 integration tests（含被選 integration-tier sharded body 的 shard-import wrappers），再加固定掃全 repo 清單；全量 integration 由 `devpro:rule-governance` 每個 mode 與 release 承接，full suite 本身改為 report-only 全量量測（不 block）**。

**Test suite manifest（unit / integration SSOT）**：`.devpro/scripts/test-suite-manifest.mjs` 為分類 SSOT。**每支新增/既有 `*.test.mjs` MUST 歸類為 `unit` 或 `integration`**——`unit`＝純 grep/import、無真 spawn/git fixture；`integration`＝真 spawn、git fixture、hook exit code、repo scan 等。`lint-test-suite-manifest.mjs` 機械驗證清單完整，並以同一 semantic detector 雙向檢查：integration 必須有實際 execution signal；unit 若執行child-process same-name named import／alias／namespace、imported Git helper／fixture、explicit test-group shard import或recursive repo-root scan即fail closed；無process binding的同名injected method、dynamic import alone、純import、comment、string/template/regex data與grep/source guard仍可為unit。**MUST NOT** 新增未歸類的 test 檔。

**Guard ceiling ratchet**：`grep-guard-ceiling-ratchet.test.mjs`（unit tier）要求引用高風險載體（`AGENTS.md`、`design-core.md`、`security-coding.md`、`database-conventions.md`、`ai-autonomy.md`、`security-scanning.md`）的字面守門測試（檔名結尾為 `-grep` 或 `-guard`）在自身原始碼宣告 guarantee ceiling；宣告須是以 `Guarantee ceiling` 或 `保證上限` 開頭的註解行，只出現在 assert、regex、字串 fixture 或測試標題裡的同樣字眼不算。未宣告者須列於該測試檔內的基線，基線**只減不增**（基線＝引入時凍結的名單扣掉已退役名單；凍結名單以固定數量與 digest 釘住、不得改；退役一條就寫進退役名單；條目補了宣告卻未退役、退役名單出現凍結名單外的名字、guard 檔消失、或不再引用高風險載體，皆轉紅）。此閘只驗「有沒有宣告」，不驗宣告是否誠實；準確性與語意漂移仍歸 review（見 `rule-anchor-guard-strength.md`）。

**Tier-aware 執行時機（`run-test-suite.mjs`）**：

- **預設只跑 unit tier**：`node .devpro/scripts/run-test-suite.mjs --tier unit`（~2–5s）。
- **PR latency fast gate（明示選取）**：`node .devpro/scripts/run-test-suite.mjs --tier fast` 先跑完整 `unit` tier，再跑 runner 內固定、可審計的代表性 integration carrier set；它只提供 `<60s` 內的快速回饋，不是 coverage-complete suite，也不得取代 `--changed <base>` 的 canonical final evidence 或 `--tier all` 的 exhaustive outcome。fast set 的每個檔案 MUST 存在於 `test-suite-manifest.mjs` 且維持 `integration` 分類；任何 child fail 仍使 fast gate non-zero。
- **效能調查閉環（SSOT）**：任何以降低整體 tier／full-suite wall-clock 為目標的工作，MUST 先讀 `test-performance-patterns.md` §Measurement-Driven Optimization Loop，依序完成 canonical baseline、process／I/O profiler、critical-path 排序、根因研究、bounded POC、驗證後擴大、整體重測與 stop-loss；不得只調整 Git／Node process 數量或以局部百分比相加宣稱成效。
- **Fast carrier admission（新增測試的判定鏈）**：新增 `unit` test **MUST NOT** 放進 fast set。新增 `integration` test 只有在「它代表目前 fast set 尚未涵蓋的新核心載體／真路徑」且同類沒有既有代表列時才可候選；已有同類代表列時留在 exhaustive tier，不為湊 coverage 重複加入。候選必須先通過 manifest=`integration`、真 process／Git／hook lifecycle、非重複與 focused correctness 檢查，加入後再量測 `--tier fast` 仍 `<60s`；任一條件不成立就不加入，並在 QA 記錄排除理由。每次 admission 必須同一 change 同步更新 fast constant、membership guard、規範與可重跑 evidence；不得靠 glob 或自動把所有新 integration tests 塞入 fast set。
- **`--changed <base>` 機械判定**：`run-test-suite.mjs --changed main` 讀 `git diff <base>...HEAD --name-only`（另查一次 `--diff-filter=D` 取刪除集合、一次 `--name-status -z --diff-filter=R` 取 rename 舊路徑），**永遠跑完整 unit tier**；integration 選 **changed manifest integration tests**（本 PR 新增或修改的 integration-tier `*.test.mjs`）聯集 **引用被改腳本的整合測試**——原始碼逐字含被改非測試腳本（`.devpro/scripts/**/*.mjs`，不含 `tests/`；被刪或 rename 的腳本另計舊路徑）完整 repo 相對路徑的 manifest integration tests（單跳；每個 `/` 也可寫成相鄰的引號字串，如 `".devpro", "scripts", "prune-merged-local.mjs"`，但每段都要依序出現；不比 basename、不追 import、不遞迴、無 seed）；以上兩者再聯集其 **shard-import wrappers**——以任一被選的 integration-tier sharded body 為 shard-import 目標、一跳機械推導出的 wrapper tests；changed unit-tier test 不展開任何 wrapper。scoped 時另跑固定清單 `REPO_SWEEP_INTEGRATION_TESTS`（掃全 repo、任何檔變動都可能轉紅），印 `repo_sweep files=<n> paths=<…>`；新增此類測試 MUST 登記（大檔內的先搬成小檔），漏登記只能等 `--tier all`。被改腳本沒有任何整合測試引用時不選、不 fallback。有被改腳本且 scoped 時多印 `script_references carriers=<n> referencing_files=<k> unreferenced=<m>`（m>0 時附 `unreferenced_paths=`）揭露無引用者；fallback 時不印。並輸出 `integration_files=<selected>/<total>` 與 `selection=scoped`；選到 0 個時同樣輸出 `integration_files=0/<total> selection=scoped`，不啟動 integration child run、不印 `tier=integration` terminal 行，exit code 只看 unit。已知路徑（known path，不會 fallback）：`.devpro/scripts/**` 下的非 test 檔——其中 `.mjs` 腳本只經上述引用查找帶進測試，`tests/lib/*.mjs` helper、`tests/fixtures/**` 與 `hooks-git/` 下無 `.mjs` 副檔名的 git-native hook 不是引用來源、自身不選——以及 `.claude/**`、`.opencode/**`、`.codex/**`、`.cursor/**`、`**/SKILL.md`、`.gitattributes`、repo 根目錄 `.gitignore`、`notes/**`、`openspec/**`、`*.md`；git name-status 為 `D` 的 suite test 同屬已知路徑。changed set 空/不可得或 rename 來源無法判定（`changed-set-unavailable`）、路徑分類為 unknown（`unknown-path`）、selector、引用查找（任一整合測試原始碼讀不到）或 shard detector 拋錯（`selector-error`）、plan invariant 不成立（`selection-unexplained`）時 MUST fail closed 回完整 integration tier，並輸出具名 `full-fallback:<reason>`（`EXIT_FULL_FALLBACK=75`，除非帶 `--allow-full-fallback`）。這是pre-PR Step 1的預設驗收路徑；`--tier fast|integration|all`、release與consumer routes不走此file selector。
- **PR-stage integration 證據範圍**：PR 階段的 integration 證據範圍＝完整 unit tier＋本 PR 新增／修改的 integration tests（含被改 integration-tier sharded body 的 shard-import wrappers）；其他 integration tests（包括未改 test 的 hook、script、`SKILL.md` 等 carrier 對應的 tests）與 `--tier all` 的證據缺席 **MUST NOT** 列為 finding；全量 integration 屬 `devpro:rule-governance`（見下方 governance bullet）與 release（見下方 full suite bullet）。reviewer 對某個未改 test 有具體疑慮時，仍可 scoped rerun 並記錄疑慮；缺證據本身不構成 finding。`--changed` 因引用被改腳本或掃全 repo 清單多帶進的未改 test 是額外保險，多跑不擴大上述義務。
- **consumer rules tag 例外／consumer context 先分流**：runner MUST 先辨識 direct consumer root（Mode A）或 Git 驗證的 consumer-owned true `.devpro-agent-rules` submodule（Mode B）。在這兩種 consumer context 中，`node .devpro/scripts/run-test-suite.mjs --changed production-YYYYMMDD-rules[-n]` MUST 跑 consumer rules smoke，而非 source-maintainer suite tier：`git submodule update --init .devpro-agent-rules`、submodule `--sync`、root `sync-agent-rules.mjs --check`、root `devpro-doctor.mjs --consumer-smoke`、`multi-runtime-parity.test.mjs`、`hook-pre-tool-gate-git-flow.test.mjs`；其他 default／`--changed`／`--tier all`／explicit-tier 路徑 MUST 標示 source-maintainer-only corpus checks 為 `N/A` 並 exit 0，不得進入 source tier selection。只有 source repo 或 ownership 無法驗證的 root 仍走上方 tier selection，且不得回傳 consumer `N/A`。consumer 的 canonical-suite 收據（`notes/qa-regression-head-<change>.json`／R6）同為 source-maintainer-only：consumer 以自身「專案約定測試指令」的 suite 證據為準，pre-existing／環境型失敗依下方 Exit Criteria 的 suite×HEAD／digest 綁定段與 `ai-autonomy.md` §Stop-Point Next Step Contract 誠實記錄；不新增機械豁免、不得冒充綠。`seal-final` 只在 direct consumer（Mode A）判定下封存 `not-applicable-consumer-profile`（N/A，不代表專案測試已跑）；Mode B 仍 fail closed。
- **consumer pre-PR checks 並存**：consumer 的 `.devpro/pre-pr-checks.local.md` 與 pre-PR Step 1 專案測試、`qa-test-scope.md` 的 `ui smoke:`、`E2E:`、`DEV deploy-verify:` 並存，該檔不取代其中任何一項，反之亦然；`run-test-suite.mjs` 的 consumer route 與 `seal-final` 的 consumer N/A 不變；契約見 `.devpro/agent-rules/consumer-pre-pr-checks.md` §Consumer Pre-PR Checks。
- **full suite 為 release、`devpro:rule-governance`，或本節其他明示例外**：`node .devpro/scripts/run-test-suite.mjs --tier all`。此 canonical path 依 manifest 先跑 unit、再跑 integration，並回報 aggregate `tier=all` wall-clock；raw `node --test .devpro/scripts/tests/` 只可作低階診斷，不作 canonical timing，因為它會讓 Node 對所有檔案做 concurrent directory discovery，可能放大 integration-heavy contention。`--tier fast` 的通過不得覆蓋或改寫此 exhaustive outcome；可由 CI／背景工作後置或平行執行。非每 PR 必跑，但 release、`devpro:rule-governance`，或本節其他明示例外仍 MUST 跑。
- **Governance 全量與紅燈處置**：`devpro:rule-governance` 的 `audit-only`、`split-dedup-review`、`convergence-loop` 三個 mode，MUST 在任何 mode 專屬步驟之前先跑 `node .devpro/scripts/run-test-suite.mjs --tier all`，並記錄 HEAD SHA 與具名 log path；此步不得跳過，也不得降級成 `--tier fast`。紅燈處置：`convergence-loop` 同一輪經 `devpro:change`／OpenSpec lane 修到全綠才繼續 sweep；`audit-only`、`split-dedup-review` 這兩個 mode 不改檔，把紅燈記成 finding（含失敗 test 名與 log path，risk tier 依 `rule-audit-playbook.md`），再 route 到修正 lane。consumer root：runner 印 `source-maintainer checks: N/A` 並 exit 0，視為 N/A，不算紅燈。

**Worker focused + canonical final change-scoped suite（SSOT）**：

- **Worker**：完成 claimed／touched carriers 後 MUST 跑 focused RED／GREEN + required lint，並交付可重跑 command／log path；remediation worker **MUST NOT** 被 handoff 政策要求預設跑 `--tier all`，focused evidence 也不冒充 final readiness。
- **Canonical owner**：primary full在committed active artifacts收斂且archive fixed gates通過後，恰好一位owner由existing `seal-final`執行唯一一次`node .devpro/scripts/run-test-suite.mjs --changed main`。helper自行驗clean HEAD/main、terminal receipt、Git-derived manifest與`direct|archive_transition` coverage；caller/same-agent/transcript/manual claims非authority。
- **Merge evidence（source Local-Test Gate）**：`gh pr merge` 對 code／rule-carrier PR 的本機測試證據只認三形擇一，缺一律 block：(1) exact-head receipt——`notes/qa-regression-head-*.json` 的 `head_sha` 等於 PR head 且 `suite_evidence` pass／fail=0；(2) 同 change 的 bookkeeping tip-move receipt——receipt 同樣須 `suite_evidence` pass／fail=0，且只接受 `evaluateRegressionHeadCurrency` 回 `kind: current-bookkeeping-tip-move`，屬 currency 判定而非 PR head 的 suite 證據，不解除 seal-final 在 archive head 重新跑一次 canonical change-scoped suite 的義務；(3) PR head 上同 change、head-bound 的 seal-final FinalEvidenceRecord，經有界 verifier process 驗證，任何失敗即本形不成立（(1)/(2) 成立仍放行）；只有 `result: pass` 紀錄成立，consumer N/A 紀錄不成立。走完正常流程 seal-final 後不必再手記 receipt。細節見 `pre-tool-mechanical-gates` spec「Local-Test Gate Merge Advisory」requirement。
- **Transition/FinalEvidenceRecord**：Git/durable transition valid時MUST NOT second primary full；invalid/non-equivalent/後續commit=>`full_reopen_required`（PR 開出後 cross-model 在 archive 後指出的 rule／code／test 載體修復不適用此重開，見 `post-pr-warn-repair.md` §Post-archive 載體修復的證據對齊）。record綁exact clean HEAD、coverage、receipt、complete manifest、immutable log、suite result（source 為 pass 與計數；consumer 為 `not-applicable-consumer-profile` 與 `null` 計數）；repair/closure/content manifest不可替代。fixed gates見devpro:pre-pr `Post-Ledger Final Evidence Gate`。
- **Invalidation**：carrier edit使`FinalEvidenceRecord` invalid，review lineage/valid receipt保持；absent/failed/stale/mismatch或same-HEAD dirty只阻readiness、不抹coverage。後續commit full reopen；新authorized clean HEAD才產唯一record；byte-identical retry可idempotent，different bytes/第二authority fail closed。
- **`--tier all`**：release、`devpro:rule-governance`，或本節其他明示例外；`multi-agent-handoff.md` 只可 pointer 至此，**不得**另立 worker `--tier all` 政策正文。

**每次跑 tests MUST 回報耗時**：`run-test-suite.mjs` 每次 run 印 `[test-suite] tier=<t> real=<s>s status=<pass|fail>`（wall-clock）；`--tier all` 會額外印 final aggregate `tier=all` real/status。`check-suite-runtime-budget.mjs` 為 **report-only** 全量量測——透過 canonical runner 實跑 full suite、印 wall-clock real time，**不再 block on 固定預算**（無 90s 硬閘、無 `DEVPRO_SUITE_BUDGET_BYPASS`／`DEVPRO_SUITE_BUDGET_SECONDS`）；**紅 suite（有 fail）仍 exit 1**（紅 suite 非有效量測）。

**但「回報耗時」是 run-time 可見度，不等於驗收證據**——兩者是不同用途，不得互相取代。runner 把 `real=<s>s` 只 `console.log` 出來，**寫進具名 log 的是 child 的 TAP 輸出**，log 摘要回讀的是 `lines`／`bytes`／`tests`／`pass`／`fail`，**沒有任何一個欄位帶秒數**。因此那個數字一旦捲出 console 就沒有載體可回頭查證：它既不能被重讀，也不能被重算。**把 wall-clock 寫進驗收證據行 MUST NOT 發生**——沒有人能事後獨立覆核。驗收證據 MUST 取自**能被重讀的載體**：具名 log 的路徑與其 `tests=`／`pass=`／`fail=` 計數、失敗測試名、exit code。要談效能就回到本節的 report-only 量測用途，不要讓它冒充完成證據。

- grep / rule-lock：加到既有同主題檔；不要為單一 grep assertion 新增 test file。
- 觸及 git repo / worktree fixture、hook spawn、Node process spawn、repo scan、大量 fixture copy 的測試 → 歸 integration tier，並先做 focused timing。
- 完成證據取**最終狀態**那次 run 的具名 log 與其計數（runner 印的 `log=<path> … tests=/pass=/fail=`）；不得沿用中途、修好前、或不同 commit 的 run。`real` time 屬 run-time 可見度而非完成證據（見上段）。

新增/修改觸及 spawn（git/hook/CLI/repo scan）的測試時，作者 MUST 先讀 `test-performance-patterns.md`（成本來自 spawn 非 test 數；四 pattern：昂貴 fixture 整檔共用一次／多斷言合併到單次 spawn／能 import 就別 spawn 整腳本／源碼熱點迴圈內 per-item spawn 改一次 batch；反模式：拆檔降 wall-clock 對 CPU-bound suite 無效）。此優化為降低 integration tier 成本用，非為通過任何 wall-clock 硬閘（已無）。

### Gate／release 級套件：同 repo exclusivity（正確性 ≠ 量測安靜）

量測隔離只保證 wall-clock 可信；**gate／release-tier suite 正確性**另要求同 repo 的 live git topology 在跑測期間不被並行改寫。對 gate／release 級套件跑（例如 `node .devpro/scripts/run-test-suite.mjs --changed main`、release terminal suite）期間，同一個 git repo **MUST NOT** 並行執行會變更 shared live topology 的操作：

- `git worktree add`／`git worktree remove`
- `git merge`（含把其他 ref 合進此 repo 任一 worktree）
- 會切換／覆寫 shared checkout 狀態的 disruptive `git checkout`／`git switch`（含帶 pathspec 物化）

並行 worktree add／merge／disruptive checkout 會讓 suite 讀到半套 tree 或錯 HEAD，產**假紅**（正確性失敗），即使機器很安靜、量測隔離已滿足。量測安靜 ≠ exclusivity；兩者同時必要。

> 上段所稱「量測隔離」見 `test-performance-patterns.md` §量測隔離（wall-clock 前置）。
