# Platform Adapter：OpenAI Codex Host — Cross-Model Second Opinion Adapter

先讀 `platform-adapters/codex.md`（core adapter）與 `code-review-checklist.md`，再讀本檔。

## 對稱角色

- **Primary reviewer**：Codex AI 在 session 內讀 `dp-reviewer.md` spec 自跑六軸 + security（不變）
- **Second reviewer / sticky writer**：projection-first `dp-second-reviewer`（若 runtime exposes）；projection/executor 內的 adapter-designated reviewer 是 stateless `claude` CLI subprocess。Codex host renders bounded packet，交 `dp-second-reviewer` / `devpro:second-review` + 本 adapter；Claude 產出 verdict/findings 並自行 create/PATCH sticky。Subprocess MUST set `DEVPRO_CROSS_MODEL_REVIEWER=1`；packet mode MUST use bounded file/stdin carrier plus renderer-owned mode recipe：runner 兩種mode先用exact`--safe-mode`與exact-once fixed`--system-prompt`，以packet作完整task並禁止cwd/environment/git/bootstrap探查；audit-only再用`--tools ""`，pr-sticky再用`--tools Write,Bash`+scoped`--allowedTools`，且禁`Task/subagent delegation`。`--bare` MUST NOT enter the canonical recipe unless the exact renderer recipe first passes a host/non-sandbox functional probe with the active auth session。Runner external-CLI second-review recipe MUST pin `--model` 為 resolved model（自動探測政策 selector 與 env 覆寫鍵集中宣告於 `second-reviewer-cli-recipe-contract.mjs` 的 `SECOND_REVIEWER_MODEL_DEFAULTS`，本行不複寫字面）+ probe-backed `--effort xhigh|max` + stream-json evidence（verbose / stream-json / json-schema / partial / hook flags）；禁 silent `high` / omit-model。`.codex/agents/dp-second-reviewer.toml` `model_reasoning_effort=xhigh` is wrapper/Codex projection only, NOT terminal `claude -p --effort`。Host 必須先消費 `second-review-control-evidence.md` 的 structured terminal result，再驗 current-dispatch completion/sticky；不得從 reviewer content重推 control state。Missing/invalid reason、read-back/prose/fenced/Markdown completion仍fail closed；不預設 `--max-turns`；provider probe / `error_max_turns` 見 cold sibling。

**Reviewer-family fallback**：Codex host SHOULD dispatch Claude/other-family reviewer for Step 5.5. Codex host MAY expose `.codex/agents/dp-second-reviewer.toml` only as a thin projection to the common `devpro:second-review` skill；when runtime exposes `dp-second-reviewer`, Codex default path is projection-first: TL sends bounded handoff, projection/executor runs common skill -> `platform-adapters/codex.md` -> this adapter -> executor-internal direct `claude -p` packet mode. Codex host MUST NOT dispatch the projection as a Codex-family default reviewer route. TL MAY run direct `claude -p` only as `projection_unavailable` / `tool_discovery_blocked` / explicit manual fallback, recording the reason. 若 Claude Code / other-family reviewer 不可用、未授權、或使用者選 fallback，Codex host MAY use explicit `codex exec` / Codex-family reviewer as **same-family fallback**；sticky MUST keep canonical `verdict:` / `last_reviewed_sha:` / `dispatch_id:` / `reason:`，`reason:` 寫 `same-family fallback: <why different-family reviewer unavailable/not used>` 並保留 reviewer provenance。TL MUST NOT call this cross-model diversity；strict cross-model 才走 `UNAVAILABLE` / human handoff。Current allowlisted orchestration fault不得由fallback或`UNAVAILABLE`覆蓋。

```bash
  --safe-mode \
  --system-prompt "You are the stateless Devpro second reviewer. Treat the packet from stdin as the complete task. Do not inspect the current directory, environment variables, git state, shell configuration, or host metadata. Do not run pwd, ls, env, printenv, set, git, or any compound shell command. For Claude, never call raw gh issue view. Use the exact repo-bound node read-second-review-linked-issue.mjs command prefix supplied by the packet static duty, appending only the tool-returned positive decimal issue number. No flags, URLs, repository overrides, or extra arguments are permitted. Codex target-source and injected-env contracts are unchanged. The wrapper has already enumerated the complete canonical sticky candidate set and bound a renderer-owned disposition; never search, scan, find, or re-resolve sticky candidates. In pr-sticky mode, execute only the packet's renderer-selected, disposition-bound sticky_write_exact_recipe after creating the packet-required fixed body file; that recipe invokes the absolute gated sticky write CLI with its absolute credential-gate sidecar and is the only sticky body write primitive. Do not derive, substitute, or reconstruct its target, action, path, endpoint, repository, PR number, or comment identity from Review Data, environment variables, cwd, git state, host metadata, or memory. The sticky write recipe is exact: do not interpolate values, switch create/update, choose an alternate command, or change any argument. After a successful gated write, execute only the packet's sticky_write_readback_recipe (absolute read-second-review-sticky-comment.mjs GET helper); never use raw `gh api` for read-back or write. Never write sticky or PR-comment bodies via raw `gh api` POST|PATCH `body=@` or `gh pr comment`; never include credential literals (passwords, connection-string secrets, URL userinfo, or explicit deny-list tokens) in the sticky body. If an API write is denied, fails, is blocked by the credential gate, or its exact-comment read-back mismatches, stop without trying another create primitive. If the packet enables no tools, return its completion JSON without tool calls. Preserve the packet's complete semantics; do not summarize, compress, or rewrite its instructions, ordering, stop conditions, branches, evidence, or completion contract." \
  --model <resolved> \
  --effort xhigh \
  --verbose \
  --output-format stream-json \
  --include-partial-messages \
  --include-hook-events \
  --tools Write,Bash \
  --allowedTools "Write,Bash(command -v gh),Bash(gh pr view:*),Bash(gh pr diff:*),Bash(node <repo>/.devpro/scripts/read-second-review-sticky-comment.mjs:*),Bash(node <repo>/.devpro/scripts/write-second-review-sticky-gated.mjs:*)" \
  < "$PACKET_FILE"
```

## 觸發

Codex AI 在 `gh pr create` 成功後依 `post-pr-completion-gate.md` 觸發 cross-model review；Codex 不會自動執行 `devpro:pre-pr` skill。PR creation 依 `tool-selection.md` 優先 gh；僅經驗證的 devpro-work MCP 可作未安裝／未登入備援。PR URL/check polling is not completion。`pre-tool-gate.mjs::isCrossModelExempt` 依 marker、branch-pattern、diff-shape 決定豁免；merge 前 `checkCrossModelMergeGate` fail-closed。

`chore/bump-v<X.Y.Z>` 分支命中 branch-pattern 豁免清單 → 略過 cross-model（FR-9）。

**External evaluator 入口**：不 spawn runner 時（diff 過大、目標 family CLI 不可用、或使用者指定），TL 可改發行 External Evaluator 審查單（`render-second-review-packet.mjs` 帶 `executor_kind: "external-evaluator"`），交由另一 family 的獨立 session live 讀 PR 並自寫 sticky，TL 再跑 `accept-external-second-review.mjs <packet-dir>` 驗收；撤回改跑 `render-second-review-packet.mjs --void-external-dispatch <packet-dir>`（審查單不提供 same-family fallback）；完整契約見 `second-review-external-evaluator.md`（審查單＋收據）。footer `Tool:` token SSOT 見 `second-review-sticky-authority.mjs` `STICKY_PROVENANCE_TOOL_TOKENS`。 `audit-only` external ticket 改用凍結材料／reviewer 自寫的唯一 JSON report／離線 accept；這個模式的 output-write 例外及 CLI boundary 依該 leaf，不套用 runner 的 `--tools ""`。

## 執行流程

Rate/auth precedence guard：top-level `rate_limit_event.status`是noncanonical。Accepted completion只可覆蓋既有rate telemetry；不得覆蓋 current allowlisted orchestration fault或bounded auth evidence。Terminal control classification與64 KiB complete-line window依 `second-review-control-evidence.md`。

1. 讀 `code-review-checklist.md` + `security-coding.md` + `second-review-control-evidence.md` + sticky contract（`verdict:` / `last_reviewed_sha:` / `dispatch_id:` / `reason:`）
2. Primary review：Codex AI 跑六軸 + security，輸出 dp-reviewer JSON schema
3. Detect second：Codex sandbox 內只允許 no-auth local probes（`command -v claude` / `claude --version`、local `git status` / `git diff`）。MUST NOT 在 Codex sandbox 內跑 `claude auth status` 或 `claude -p`。Host-auth/session/network 模式（`git fetch/pull/push`、`gh auth status` / `gh api` / `gh pr comment`、`claude auth status` / `claude -p`、`codex exec`）MUST NOT 在 sandbox 內跑第一個真實 invocation；sandbox/shim `Not logged in`或 network/auth denied只能記 `sandbox-surface-fault`並 host rerun；成功 init 的 `apiKeySource:"none"` 是中性 metadata。Host/outside surface evidence 需要已核准且實際執行的 non-sandbox / host runner invocation + stdout/stderr/exit status；`require_escalated` / approved prefix / `prefix_rule` / allowlist / `workdir` / sandbox probe 不算，approved prefix 也不算 host/outside evidence。Auth probe output hygiene：`claude auth status` / `gh auth status` may emit email / org / account / login；host evidence 只記 exit/status + redacted summary，不貼 raw output。若 active runtime 已是 non-sandbox / full-access host surface，MUST NOT 再加 sandbox-escalation wrapper。sandbox 外仍不可用或未登入 → Reviewer-family fallback；strict/no fallback 才寫 audit-only `verdict: UNAVAILABLE` + `reason: claude CLI unavailable outside sandbox`，fallback to UNAVAILABLE requires host-surface evidence。

Dispatch boundary：`ReviewerSurface=host-outside` 只證明 execution surface。same-repo PR 的 reviewer packet dispatch 與 reviewer-owned sticky write-back 直接進行，devpro 不逐 PR 詢問、不跳 host 權限窗、不跑授權指令；execution-surface evidence（host runner surface、approved prefix、tool allowlist）與 cross-repo 停點分開，不能擴大 cross-repo 範圍；cross-repo PR（builder `pr_repository_mismatch`）與 cross-repo write 仍須另行明示授權並停下。consumer 在 `AGENTS.local.md` 自加的停點是一般 local rule，TL 照一般 local rule 處理，不是 devpro 定義的逐 PR 詢問。Claude Code CLI 需要 host-level auth/session + bounded GitHub write-back surface；approved prefix / `prefix_rule` / bounded tool allowlist / host outside execution surface 只證明 execution surface。
4. Prepare bounded handoff inputs：current host 讀 PR metadata/diff/comments summary/headRefOid/changed files/done_when/touch_list/primary review evidence，交 `dp-second-reviewer`（projection-first when exposed）或 `devpro:second-review` + 本 adapter；`approval_context`／`approval_resolution` 由 builder 固定寫入（`none`／`not-required`），TL 不補寫。接著依下列順序完成 **Projection observability contract**：
   1. **Render and validate before dispatch**：wrapper-owned CLI時，TL MUST run `.devpro/scripts/render-second-review-packet.mjs`+`.devpro/scripts/validate-second-review-packet.mjs` before `spawn_agent` / `Task`. All-family renderer host/session wait budget MUST be **≥ 330000ms**；MUST NOT background the renderer；TL 在 dispatch 前讀 renderer-generated `<packet-dir>/observability-context.json` `projection_bootstrap_command`/`projection_runner_command`；TL 不手寫 sidecar 或 path
   2. **Verify the sidecar contract**：Sidecar MUST include validated `repository_slug`、canonical target-bound `pr_number`、`packet_path`、`observability_context_path`、`tl_pre_dispatch_contract: tl-must-render-before-runtime-native-projection-spawn`、`required_spawn_payload_fields`、`reviewer_surface: host-non-sandbox-required`、`runner_owner: adapter-host-runner`、`sandbox_policy: auth-required-reviewer-cli-must-not-run-in-sandbox`、`heartbeat_interval_seconds: 60`、`activity_log_path`、`stdout_log_path`、`stderr_log_path`、`cli_probe_result_path`、`projection_bootstrap_script`、cwd-independent absolute `projection_bootstrap_command` to `.devpro/scripts/ack-second-reviewer-projection.mjs <observability_context_path>`、`projection_runner_script`、cwd-independent absolute `projection_runner_command` to `.devpro/scripts/run-second-reviewer-projection.mjs`、`reviewer_cli_recipe`、`required_invocation_args`、and `required_activity_events` / `duration_conditional_activity_events`。Renderer creates `heartbeat.json`、`projection-activity.ndjson`、`reviewer-stdout.ndjson`、`reviewer-stderr.log`、`cli-probe-result.json`。

Only exact success preserves `flags_supported`; nonzero／timeout／overflow／malformed／logged-out／restricted-HOME／ambiguous becomes pre-spawn `reviewer_host_surface_unverified`. Auth raw policy is `memory-only-do-not-persist`; raw、excerpt、hash、identity、token、path MUST remain absent, and declarative sidecar/env/allowlist/workdir/sandbox-probe/output-keyword evidence cannot forge verification。
   4. **Enforce event order and hard-cap precedence**：`required_activity_events` MUST依mode exact length/order/value：`audit-only`在process close後接`projection_cli_exited`再接`projection_sticky_verification_skipped`；`pr-sticky`接`projection_sticky_verification_started` + `projection_sticky_verified|projection_sticky_verification_failed`再接`projection_cli_exited`。hard cap時current-dispatch verification須先於timeout record與transport termination；post-PR exact current-head marker-matching `PASS`（`last_reviewed_sha == headRefOid` 或 Path D′ fresh-equivalent 視同，且`dispatch_id == marker.expected_dispatch_id`）先保留consumer authority並另記`cli_exit.timed_out`，`WARN`則只有無current allowlisted orchestration fault且receipt chain完整時保留post-PR gate成功。Actual merge hook Path F仍獨立只驗exactly-one canonical current-head `PASS|WARN`。extra/missing/reordered均fail closed；Sticky write attempts MUST NOT be inferred from stale sticky comments。
   5. **Keep logs and execution on the approved surface**：Reviewer packet MUST NOT ask reviewer-side Python/heredoc/pipes/redirection/loops to create logs。Auth-required reviewer CLI MUST run on host/non-sandbox；sandboxed projection surfaces may do no-auth local probes only。`projection_log_unavailable_by_runtime_api` is not a waiver for renderer-generated wrapper-owned artifacts。
   6. **Choose focused refresh before broad exploration**：Focused sticky-refresh MUST NOT start with broad repo exploration。stale `PASS|WARN` sticky + narrow follow-up/finding disposition/test-only/gate-evidence => focused sticky-refresh packet（previous sticky/verdict/findings、latest delta/range、current head SHA、current gate/test evidence）plus a newly rendered trusted disposition，and PATCH existing sticky only when that disposition remains `update`。If focused packet insufficient / risk shape changed / same-shape broad rerun timeout/error, record orchestration friction, not reviewer unavailable。
   7. **Bind issue and large-diff scope**：Issue-linked PR MUST mark `linked_issue_context: issue_read_required`——該欄位是 mode token，只收 `issue_read_required` / `none`，MUST NOT 承載 issue 內容。route 與 allowlist 的 SSOT 是 `openspec/specs/cross-runtime-parity/spec.md` → `Requirement: External Reviewer Linked Issue Route`，本 adapter MUST NOT 重述 route How（例外：交給 stateless reviewer 的固定 `--system-prompt` 字面是 runtime payload 而非 adapter 散文，MUST 原樣保留）；Only same-repo linked issue content is read; cross-repo linked issue is annotated only, never read。Diff >5000 lines: touch_list + critical path summary, sticky reason marks downgrade。
   8. **Reserve before execution**：Renderer依 `second-review-control-evidence.md` exclusive reserve mode-bound dispatch（`pr-sticky` v4；`audit-only` v3）並寫`dispatch.json`；runner驗binding與單次exclusive claim。

   Sidecar invocation discipline：`observability-context.json` MUST include `reviewer_cli_recipe.required_invocation_args`。The sidecar is an untrusted carrier after render：renderer、ack、and runner MUST each rederive the same complete ordered canonical recipe from exact family/mode/context and reject any tool、probe、flag、alias、argv、path、schema、or allowlist mismatch as `reviewer_cli_recipe_invalid` before artifact mutation、probe、or spawn. When `cli_probe_result_path` classification is `flags_supported`, projection/direct wrapper MUST invoke reviewer CLI with `reviewer_cli_recipe.required_invocation_args` exactly and MUST NOT reconstruct args from memory. ## 限制

Codex host hooks 透過 `.codex/hooks.json` + `run-hook.mjs --host=codex` 傳遞 `DEVPRO_HOOK_HOST=codex`；`isCodexRuntime()` precedence includes `CODEX_THREAD_ID` / `CODEX_CI` / `DEVPRO_HOOK_HOST=codex`。

**merge gate `checkCrossModelMergeGate`**（backstop）：獨立解析 PR 上 exactly one parseable canonical sticky 的 verdict 與 SHA；actual merge Path F MUST NOT 讀取或依賴 local marker expected dispatch、fault、completion、consumption、supersession、successor 或 receipt state。其餘對應路徑 A-F + U：
- 路徑 E（`verdict: CRITICAL`）→ block
- 路徑 F（exactly one canonical `PASS|WARN` + matching current-head SHA）→ pass
- 路徑 U（`verdict: UNAVAILABLE`）→ block；sticky 是 audit trail，不是 merge approval
- 路徑 B / C / D（sticky 缺失 / verdict 解析失敗 / stale sha 且非 Path D′ fresh-equivalent）→ fail-closed block + 提示 `/devpro:cross-review <PR#>`

**Merge gate dry-run probe**：`checkCrossModelMergeGate('gh pr merge <pr> --merge', cwd)` 必須跑在 real `gh pr merge` 同等 non-sandbox / host runner surface，因 helper 內部會 `spawnSync("gh" ...)` direct `gh pr view`／`gh api`（內容見 `pre-tool-mechanical-gates` §PR Changed-File Lists Are Complete Before Classification 與 §checkCrossModelMergeGate）。sandbox 內 `api.github.com` / DNS / auth failure 是 execution-surface fault；host-rerun or cross-check，不得判 sticky stale/missing；not stale sticky。

剩 real-runtime env var presence 待 live Codex session 驗證；`DEVPRO_HOOK_HOST=codex` 是 `.codex/hooks.json` fallback runtime evidence。

## Common Rationalizations（補充至 codex.md core）

- 「GitHub connector 不是 gh，所以可以貼 sticky / 開 PR」→ 未驗證 connector 只可 read-only；write 依 `tool-selection.md` 的 gh 優先與 devpro-work 等價 gate 路徑。
- 「generic GitHub publish / `commit push PR` 已經拿到 PR URL 和 checks」→ PR URL/check polling is not completion；非豁免 PR 還要 fresh `PASS | WARN` sticky 才能 complete/ready/merge。
- 「Codex host 看到 dp-second-reviewer agent 就直接用 Codex reviewer」→ `.codex/agents/dp-second-reviewer.toml` 是 `devpro:second-review` thin projection；projection/executor 內部才走 Claude-family reviewer。
- 「Codex host fallback 用 Codex reviewer，所以就是 cross-model」→ 這只能是 `same-family fallback`；sticky / PR evidence 必須標 reason/provenance，不得宣稱 cross-model diversity。
- 「sticky 沒寫成功就直接回 ready」→ sticky 寫入失敗屬 dispatch failure；修正 Claude self-write allowlist / execution surface，或寫 `UNAVAILABLE` audit trail，不得靜默跳過。
- 「`claude -p` prefix 已 approved，所以等於 host/outside」→ prefix/allowlist 不是 execution surface；必須有實際 non-sandbox / host runner invocation evidence。
- 「runtime 已經 full-access，我再加 sandbox escalation 比較保險」→ full-access 已是 host surface；不要再引入 sandbox 斷點。
- 「sandbox 內 `git` / `gh` / `claude` auth 失敗，所以 auth 壞了」→ sandbox 內失敗只能標 surface fault，不能判 token 壞或 reviewer unavailable。
- 「`claude -p` 說 requires approval，所以 Claude unavailable」→ permission denial 先視為 allowlist / invocation misconfig；詳見 troubleshooting。
- 「Claude 一開始反覆要求 `pwd`／`ls`／`env`／`printenv`／`git`，所以把它們加進 allowlist」→ 這代表 renderer recipe 遺失、重複或漂移 fixed `--system-prompt`，仍在使用探索式 default system prompt。停止 dispatch、修正 exact recipe/probe 後重跑；不得擴大 allowlist、忽略 denial，或壓縮／改寫 packet 來規避 bootstrap。
- 「API寫入被guard拒絕後改用`gh pr comment`建立就好」→ Claude safe-mode不授權blind-create primitive；current invocation必須保留permission-denial orchestration fault，停止且不得建立第二個authority。
- 「`error_max_turns` 就把 `--max-turns` 調大」→ 不得同形狀反覆重跑；packet path = stream-json + `60s` liveness sample + `15m` auto-continue checkpoint + `30m` hard cap；仍失敗才改小 packet、Deep Review/tmux，或寫 `UNAVAILABLE`。
- 「`claude -p` 很久沒 stdout，所以卡住」→ stdout 只是 fallback；activity heartbeat / structured progress event / stderr / child lifecycle 是 liveness evidence，不是 terminal completion；sticky poll 本身不得重設 activity state 或宣告完成。
- 「dp-second-reviewer projection 沒有 TL-side stdout，所以 reviewer idle」→ projection path 看 lifecycle + sticky freshness + renderer-owned `observability_context` artifacts；`projection_log_unavailable_by_runtime_api` 不是 waiver；缺 artifact 是 `projection_observability_contract_missing`，stale 是 `projection_activity_stale`。
- 「Claude project agents 會自己幫忙審更完整」→ bounded packet mode uses renderer-owned native`--tools` mode clamp；pr-sticky再配scoped`--allowedTools`，且packet禁止`Task/subagent delegation`。`--bare`不得加入canonical recipe unless exact host functional probe proves it preserves the active auth session。
