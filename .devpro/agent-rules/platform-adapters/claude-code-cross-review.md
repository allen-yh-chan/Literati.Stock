# Platform Adapter：Claude Code CLI Cross-Review

先讀 `platform-adapters/claude-code.md`（active adapter entry leaf）。本檔是 on-demand 延伸，只在 cross-review / external-reviewer routing 觸發時載入，不隨 adapter 每 session 載入。

Reviewer-stream liveness sample 的 idle evidence MUST 明確區分「尚無 output」與「最後一次 output」：第一個 output byte 前 `last_output_at` 保持 `null`，`idle_duration_ms` 以 `process_started_at` 為基準；只有真實 output 才能切換至 `last_output_at`，不得以 process start 偽造 output time。

## When to Use

- `/devpro:cross-review`、`/devpro:pre-pr` cross-review step
- reviewer agent（`dp-second-reviewer` 等）spawn external reviewer CLI 時
- adapter 路由把 Claude Code CLI 當 external second reviewer 呼叫時

## Claude Code CLI Cross-Review Skill

Packet runner liveness：Claude packet/streaming/single-result modes use activity heartbeat / structured progress as primary liveness evidence；stdout/stderr growth is fallback evidence，and sticky polling itself MUST NOT reset activity state。No stdout alone only triggers a health probe across child process、stderr、final JSON readiness、permission-denial evidence、and current-head sticky freshness。Spawn/early-exit/auth/schema/permission faults MUST fail fast。The wrapper samples every `60s`, records a non-terminal `15m` checkpoint and continues automatically, then final-verifies/classifies and terminates at the `30m` total hard cap；callback/process close is the terminal signal。

當其他 host 把 Claude Code CLI 當 external second reviewer 呼叫時，先讀 `code-review-cross-model-cli-contract.md` §External Reviewer CLI Skill Contract，再讀完整 skill：`.devpro/agent-skills-refs/autonomous-ai-agents/claude-code/SKILL.md`（direct copy from `refs/hermes-agent-main/skills/autonomous-ai-agents/claude-code/SKILL.md`）。本段只列本 repo cross-review 的固定收斂點；完整 CLI 規則以 skill 檔為準。直拷 skill 內若出現上游原生 `.claude/skills/` 範例，只是 upstream CLI 說明；本 repo 的 skill storage 一律是 `.devpro/agent-skills/`。

Prereq：`command -v claude`、`claude --version`、host-only auth probe（若使用 `claude auth status --text`，只可在 non-sandbox / host runner surface 做，且必須套下方 Auth probe output hygiene；Codex sandbox 內不得跑 auth-required probe）。Skill 對齊：Hermes 原則是 single-task automation 優先 Print Mode (`-p`)，tmux 用於 multi-turn interactive work；PR review pattern 分成 Quick Review（Print Mode）與 Deep Review（interactive + worktree）。Codex-host 對外部 Claude reviewer 的預設是 Quick Review packet + bounded PR sticky self-write mode：Claude 審查並直接 create/PATCH sticky，TL 不代貼 findings。

Dispatch boundary：same-repo PR 的 reviewer packet dispatch 與 reviewer-owned sticky write-back 直接進行，devpro 不逐 PR 詢問、不跳 host 權限窗、不跑授權指令；execution-surface evidence（host runner surface、approved prefix、tool allowlist）與 cross-repo 停點分開，不能擴大 cross-repo 範圍；cross-repo PR（builder `pr_repository_mismatch`）與 cross-repo write 仍須另行明示授權並停下。consumer 在 `AGENTS.local.md` 自加的停點是一般 local rule，TL 照一般 local rule 處理，不是 devpro 定義的逐 PR 詢問。

Auth-required CLI surface boundary：當 Codex-host 呼叫 Claude Code CLI 作 external reviewer 時，`claude auth status` / `claude -p`、sticky write-back 會用到 host keychain/session/OAuth/network surface；這些 MUST run only on a non-sandbox / host runner surface。Codex sandbox 內只准 `command -v claude` / `claude --version` 這類 no-auth probe；sandbox 內 `Not logged in` / permission denied / network denied 只代表 surface 錯，不得判定 Claude unavailable。若 active runtime 已是 non-sandbox / full-access host surface，host MUST NOT add a sandbox-escalation wrapper around `claude -p` because that reintroduces an approval/sandbox breakpoint.

Auth probe output hygiene：`claude auth status` output may contain identity fields such as email / org / account / login。Host evidence MUST use exit/status + redacted summary；MUST NOT write raw auth status output to transcript / recap / PR body / sticky / issue / log excerpt / repo artifact。若只有 text probe 可用，先用不回顯 raw stdout 的 host path 或 wrapper redaction，至少遮蔽 Email、Organization、Account、Login 後再進 user-visible transcript。
